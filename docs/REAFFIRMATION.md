# Reaffirm accepted knowledge

Teach can retain an accepted declaration unchanged and record a new caller endorsement. Use ordinary language such as “Keep this agreed rule exactly as it is.” No new API operation, connection setting or conflict-mode change is required. The same behavior is available to the console, direct Teach clients and the project plugin.

## Meaning and checked representation

Preparation distinguishes `reaffirmation` from `capability`, `facts` and `correction`. A reaffirmation child names 1–32 unique existing declarations in `reuse_symbols`, has empty `interfaces`, and has no source mapping. The server binds each selection to its accepted declaration hash in the captured model revision. The provider cannot submit replacement bodies through this path.

A plan can combine reaffirmation with separate learning objectives. A declaration cannot be selected twice, or reaffirmed while another child revises it or affects it through dependent definitions. New conditions and changed meanings require ordinary acquisition/correction; uncertainty about whether the accepted definition expresses the requested meaning requires clarification. This preparation profile does not reaffirm algebraic presentations.

Provider selection and its interpretation of natural language remain fallible. Exact reuse proves that the stored definition is unchanged, not that it expresses every nuance of the supplied prose. No phrase in a file grants permission, and no inferred equivalence substitutes for an exact accepted definition.

## Local publication and provenance

The coordinator creates a service-owned local episode. Bounded computation copies the pinned accepted bodies, retains their existing evidence, and attaches the selected original teaching inputs as `awm-adm-teaching-intent/1`. The ordinary ordered receipt and admission path checks the candidate, independent owner requirements, source support and publication context. No acquisition grant or provider call is created for this child. Preparation and optional completion explanation still use the configured provider and shared limits.

The model's definitions and theory root stay unchanged. Recording a new endorsement changes evidence support and creates an accepted publication revision. Previous evidence and origins remain immutable; unrelated declarations and dependent rules keep their existing support. Imported snapshots preserve the intent without requiring the original task/conversation database. Reaffirmation does not import proof status, certify human review, authenticate external facts, or change historical observations into implementation claims.

Optional `knowledge_intent: {role, basis}` on direct Teach retains the caller's actual adoption basis. This is an assertion by the local caller, not independently authenticated agreement. Unspecified intent stays unspecified.

Both backward and forward modes permit exact reaffirmation because it changes no conflicting definition. Changed definitions still require correction and ordinary conflict precedence. Cancellation, pauses, archived/deleted models, expired active-work windows and changed model/owner/connection contexts can prevent publication. The local receipt and parent outcome commit together. Replaying the same submission identity reads the retained operation; a fresh intentional endorsement can create new evidence without changing the rule.

## Results and diagnostics

The teaching summary includes `reaffirmed`, with objective/publication identifiers, selected symbols, `definitions_unchanged: true` and `acquisition_calls: 0`. Ordinary admission records expose the accepted revision, context and evidence. Checked change reports distinguish evidence updates from changed definitions. Mixed tasks report partial completion if another objective fails; a reaffirmed rule is not described as newly learned or independently proved.

Invalid empty children, missing interfaces, invalid source/reuse combinations, repeated or unknown symbols, and overlaps with corrections have readable fixed diagnostic codes/hints. Diagnostics never echo arbitrary validator input or exception context. An invalid preparation starts no learning and installs no configuration.

Fresh preparation uses `adm-teaching-preparation/22` with [reply 8](../contracts/teaching-reaffirmation-reply.schema.json), or `/23` with [reply 9](../contracts/teaching-legacy-reaffirmation-reply.schema.json) without a material manifest. Checked local plans use `awm-adm-teaching-plan/4` and `/3` respectively. Older dispatches retain their original schema/decoder; historical failures are not retried or relabeled.
